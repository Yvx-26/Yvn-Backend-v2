# 后端分批改进进度

## 第一批：资料一致性与回归测试（代码完成，2026-10-26）

- 已建档设备的空线路不再由旧绑定回填；大屏、地图、运行态势、采集绑定与旧查询使用相同优先级。
- 设备改线与线路编辑都会清理失效定位关联；移除节点不会被旧快照恢复，错误排序残留也不能解绑另一条线路的设备。
- 新线路提交只传节点编号和顺序；旧完整节点提交仍兼容，已有设备的名称、网络、采集参数不从线路草稿覆盖。
- 首次建档旧线路保留现有定位节点；更改线路编号时同步兼容入口编号，历史样本不回写。
- 旧资料接口对已建档对象转交统一保存服务。
- 用户已确认旧 `cable_info.cable_length` 单位为米；展示台账换算为千米，样本保持米。已有 managed_line 的人工长度不做猜测式批量修正，可能存在的历史错误值应另行核对。
- 保存所需的重读在事务提交前完成；设备配置读取加事务行锁。多进程并发行为仍需后续隔离 MySQL 测试，不以内存测试代替。

### 验证与发布边界

- 本批验证：后端 45 项测试通过；前端 48 项测试通过；前端类型检查、生产构建及本次修改文件的 ESLint/格式检查通过。构建仍提示既有 3D 模块体积较大，不影响本批构建通过。
- 先用回归测试复现问题，再修改实现。
- 单元、模拟连接、内存数据库测试覆盖旧资料导入、改名、排序、跨线移动、解绑、回滚及真实 ASGI 请求。
- SQLite 仅作内存关系回归；当前业务 MySQL 仅执行 SELECT 的 EXPLAIN，未执行 DDL、业务写入或数据迁移。
- 前端同时修改线路提交和保存后本地关联清理，保留其余页面行为。
- 后端先更新并重启，再使用更新后的前端保存线路；新前端的轻量节点请求不能发给未更新的旧后端。旧前端的完整节点请求可被新后端接受。
- 本轮不自动停止或重启正在采集数据的后端，不删除历史表，不提交 Git。
